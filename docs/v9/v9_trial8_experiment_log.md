## 二、实验设计与控制条件

### 1. 科学假设
在 Trial 7 中，下调主阶段学习率使情感分类面优化明显，但生成模型 Test PPL 停留在 33.58 平台未现突破。分析表明原配置 `BATCH_SIZE=32, ACCUM_STEPS=2`（等效批次 64）在 10,000 iter 期间仅执行了 5,000 次参数更新，解码器在自回归损失曲面上的步频分辨率受限。将 `ACCUM_STEPS` 下调至 1，使优化器步频翻倍至 10,000 次，在维持单步 32 样本噪声尺度的前提下，能够使自回归参数充分探索更优的极小值，推动 PPL 突破 33.0。

## 六、运行异常与工程根因审计

### 1. 异常现象描述
在 10,000 步训练完毕、双检查点成功保存后，原生 `test(model, test_set)` 阶段输出如下报错：

```text

  File "/root/autodl-tmp/CASE/src/models/common.py", line 1034, in <listcomp>

TypeError: 'int' object is not callable
```

### 2. 根因剖析 (Root Cause)
1. **内置函数名遮蔽**：
   在 [`src/models/common.py`](file:///e:/github/CASE/src/models/common.py#L997) 中，`evaluate` 函数内部对批次结果进行了解构赋值：
   ```python
   bow, kl, mim, ctx, ppl, str, acc, emotion, emotion_acc, epcl, dec_emo = model.train_one_batch(
       batch, 0, train=False
   )
   ```
2. **隐式类型绑定**：
   在 ED（EmpatheticDialogues）数据集下，策略损失 `str_loss` 恒为整数 `0`。解构语句将局部变量名 `str` 绑定为整数 `0`（`int` 类型），从而完全遮蔽了 Python 内置的 `str` 构造函数。
3. **调用失败触发**：
   随后执行至第 1034 行时：
   ```python
   pred_emo_names = [emo_map.get(int(idx), str(idx)) for idx in cur_preds]
   ```
   代码试图调用 `str(idx)` 作为键缺失时的兜底字符串。由于此时 `str` 是整数 `0`，表达式等价于 `0(idx)`，解释器随即抛出 `TypeError: 'int' object is not callable`。

### 3. 修复方案与生效验证
- **变量解耦**：将 `common.py` 中的解构变量名 `str` 改为 `strat_l`，解除对内置 `str` 的遮蔽；
- **双重防御**：将列表推导式中的 `str(idx)` 改用原生字符串插值 `f"{idx}"`，彻底规避任何 callable 依赖；
- **验证**：本地通过 Python AST 语法树静态编译与单元验证无误。
