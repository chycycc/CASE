### 2. 新发现工程异常 (缺陷 B1)
- **异常现象**：训练执行至 10,000 步结束准备返回权重时抛出异常：
  ```text
  File "/root/autodl-tmp/CASE/main.py", line 249, in train
    torch.save(model.state_dict(), ppl_best_save_path)
  NameError: name 'torch' is not defined
  ```
- **根因分析**：[`main.py`](file:///e:/github/CASE/main.py) 头部仅引入了部分子模块（`from torch.nn.init import xavier_uniform_`），未在全局命名空间执行 `import torch`。当 P0-2 尝试对 `weights_best_ppl_only`（Step 8999）执行独立落盘时，触发未定义报错。
- **影响评估**：常规复合分黄金检查点 `CASE_7499_38.7719` 已在评估循环内部通过原有机制持久化，故后续自动评测脚本与指标汇总未受损；但纯 PPL 检查点未能在磁盘生成。
- **修复方案**：在 `main.py` 顶部显式补全 `import torch`。

## 七、决策树判读与下一步工作指示 (Trial 8)

根据 [`docs/v9/v9_phase7_execution_plan.md`](file:///e:/github/CASE/docs/v9/v9_phase7_execution_plan.md) 第五章决策树判读标准：

```
Trial 7 实测结果：
Valid PPL 平台位于 38.40 ~ 38.57 之间，Test PPL 为 33.58（相比 T6 下降 0.04，处于平稳区间）
===> 命中【分支 B：持平振荡 / LR 不敏感区间】
```

### 1. 科学归因
- 降低峰值 LR 成功治愈了分类头的过拟合（EMO_acc 升至 42.25%，EMO_loss 降至 2.1005），但语言模型生成损失未能进一步突破 33.0。
- 根因在于当前训练配置为 `BATCH_SIZE=32, ACCUM_STEPS=2`（等效 Batch 64），10,000 iter 内实际参数更新仅发生 5,000 次。语言模型自回归解码器的权重演进步频不足，未能在大 Batch 带来的平滑梯度下充分探索损失曲面更深处。

### 2. Trial 8 实施方案
严格遵循指标优化导向，Trial 8 执行以下两项举措：

1. **工程热修复**：
   在 `main.py` 顶部追加 `import torch`，确保双检查点落盘机制生效。
2. **核心实验变量**：
   调整 `main.sh`：将 `ACCUM_STEPS` 从 `2` 改为 `1`（保持单步 `BATCH_SIZE=32`，零梯度累加）。
   - **理论预期**：10,000 iter 内有效参数更新次数翻倍至 10,000 次，在 24GB 显存占用安全（~12GB）的前提下，大幅增加优化器的探索分辨率，推动 Test PPL 向 32.83 逼近。
   - **超参保持**：维持 Trial 7 验证有效的 `LR=0.000576` 与 `composite_emo_loss_weight=5.0`。
