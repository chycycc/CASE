### 2.1 梯度范数分布与有效学习率还原

**裁剪的数学等价**（`src/models/CASE/model.py:2182-2189`，`clip_grad_norm_` 返回**裁剪前**范数）：

```
θ ← θ − η·g·min(1, C/||g||)  ⇒  η_eff = η · min(1, C/||g||)
```

| 配置 | 裁剪行为 | 有效 LR 缩放（相对未裁剪） | 说明 |
| :--- | :--- | ---: | :--- |
| **T11**（C=2.0） | `>2.0 比例 = 100%`，**每步必裁** | **0.323**（= 2.0/6.193） | 全程压制，学习率实际缩水约 68% |
| **T11-B**（C=6.0） | `>6.0 比例 = 50.64%` | **≈ 0.94** | 超阈步均值 ≈6.77，缩放 ≈0.886；混合 0.5064×0.886 + 0.4936×1.0 |
| **T10**（无 D8） | 无裁剪 | **1.000** | 代码未调用 `clip_grad_norm_`（日志零 `[Gradient Norm]`） |

**关键推论（C3）**：

- 中位数 **6.0091 ≈ 阈值 6.0** ⇒ **6.0 恰好切在分布中位数（50% 分位）上，不是右端**；
- ⇒ **T11-B 并未完全撤销裁剪，只解除了一半步数的截断**；
- ⇒ 若后续需要「剂量 0」的干净对照，clip 需设 **≥ 8.0**（P95 = 7.52）或直接关闭；但 **T10 已提供「无裁剪」的剂量 0 点**，无需重复实验。

> **审计留痕**：本项目此前曾判断「6.0 ≈ 分布右端」，该判断基于 T11 的 21 个固定位置采样点（max 6.0545），**已被 10000 步全量统计证伪**。此为采样外推错误的实例，记录在案。

### 2.2 PCGrad 冲突监控：方案 C 正式否决（Gate G2 闭环）

- **实测**：冲突步 3704/10000（**37.04%**），冲突步平均 `|cos| = 0.0228`；
- **几何含义**：冲突步平均夹角 = `arccos(−0.0228) = 91.31°`，即**反向分量仅 2.28%**，两任务梯度近乎正交；
- **实现位置**：`src/models/CASE/model.py:2193-2198`（仅统计已有计算量，**投影逻辑一行未改**，保持单变量）；
- **裁定**：在反向深度仅 0.02 量级下，逐层 PCGrad / MGDA 属对非瓶颈的过度工程 ⇒ **方案 C 正式否决归档**。

> **附带的项目级发现**：PCGrad 自 V8.2 起全程启用（`main.sh:158`），但**直至本次才首次测得冲突率**。此前「PCGrad 在解决多任务撕裂」的说法从未有任何数据支撑。

**T11-B 的平台中枢（≈37.5）低于 T11（≈37.7–37.9）**，说明步长恢复确实改善了语言模型的收敛底线——但**这是平台高度的差异，不是「持续下探」**。

### 4.2 dev/test 排序完全逆转（第三次实证，证伪 dev 判据）

| 实验 | dev_acc 峰值 | Test Acc |
| :--- | ---: | ---: |
| T11 | **0.4451**（@4999） | 41.83% |
| T10 | 0.4427（@7499） | **42.40%** |
| T11-B | 0.4378（@7499） | 42.21% |

**dev 排序：T11 > T10 > T11-B ｜ Test 排序：T10 > T11-B > T11 —— 完全相反。**

> **机理解释（更正）**：dev 与 test 的失配**不是**由于「随机重组」（Valid 同样 `shuffle=False`，无随机性），而是三方面口径差异的叠加：
> 1. **聚合方式**：Valid `b=32` 批次级等权（各 batch token 数不同）vs Test `b=1` 样本级；
> 2. **样本集不同**：Valid 5734 样本 vs Test 5255 样本；
> 3. **遴选偏差**：dev 峰值是 20 个点里挑最大，天然向上偏；Test 只在单一检查点上测一次。

⇒ **跨版本最终评判必须严格锚定 Test 确定性评测；dev 曲线只能作训练诊断，不得作为模型优劣判据（铁律 II）。**

## 六、Trial 12 终局判定

### 6.1 方案 A 否决（精确数学机制）

**代码事实**（`src/models/CASE/model.py:416-438`，单原型分支）：

```python
417: if getattr(self, "use_arc_margin", False) and effective_margin > 0.0 and self.training:
419:     margin_sim = all_sim.clone()
420:     target_sim = margin_sim[batch_idx, labels]
421:     if getattr(self, "arc_mode", "cos") == "angle":
431:         margin_sim[batch_idx, labels] = torch.where(cos_theta > threshold, cos_theta_m, ...)
436:     else:
438:         margin_sim[batch_idx, labels] = target_sim - effective_margin   # 当前配置走此分支
439:     logits = margin_sim / current_tau
```

**机制**：当前配置为 `arc_mode=cos`（T11-B 日志 `:95 arc_mode: cos`），margin 以 CosFace 形式 **`cos(θ) − m`** 仅作用于 `[batch_idx, labels]`（ground-truth 正类 logit）；`cos(θ+m)` 只在 `arc_mode=angle` 分支（`:421-435`）。

**否决理由**：
1. **方向反转**：对近义类**减小** margin = 放松正类的角度拉力，而**负类 logit 完全不受影响** ⇒ 误判只会更容易上升，与目标相反；
2. **标注天花板**：P0 已量化 `apprehensive` 19.86% vs 近义类 `anxious` 46.50%（差 26.6pp），配合 Silhouette 全负 ⇒ 这部分混淆源于标注一致性，调整 margin 无法消除；
3. **位置不对**：margin 只作用于正类 logit，要真正分离近义对，应给最相似的**负 logit** 加压，而非给正 logit 减 margin。

⇒ **方案 A 否决**（若未来重启，须改为「最相似负类 logit 加压」的 Per-class Negative Margin，并单独立项）。

### 6.2 方案 C 否决

冲突步平均 `|cos| = 0.0228`（夹角 91.31°，反向分量 2.28%）⇒ 多任务主干无实质恶性互斥，逐层投影属过度工程。**否决归档。**

### 6.3 主攻路线：方案 B2 —— 接口回正版（严格锚定 `docs/v9/plans/v9_trial12_upgrade_plan.md`）

| 项 | 冻结定义（**不得偏离**） |
| :--- | :--- |
| **注入通路** | **Decoder Layer 的 Self-Attention**：`Attn(Q, [K_prefix; K_text], [V_prefix; V_text])`。**严禁写成 Cross-Attention**（Cross-Attn 负责 attend 编码器输出 `ctx_enc_outputs`，是另一条通路） |
| **前缀来源** | **选项 (iii)：原型初值 + 可学习微调**（`nn.Parameter(prototypes_init)`），端到端训练 |
