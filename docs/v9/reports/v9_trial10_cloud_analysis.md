## 一、PPL 口径审计（本报告的前置裁决，铁律 III）

### 1. 实测口径确认

云端日志尾部（L7581-L7585）显示测试集评测进度为 `0/5255`，即 **Test 评测的 `batch_size=1`**，共 5255 个 batch（= 测试集样本数）。

聚合方式（[model.py:2054](../../../src/models/CASE/model.py) → [model.py:2212](../../../src/models/CASE/model.py) → [eval_pipeline.py:355](../../../src/scripts/eval_pipeline.py)）：

```
ctx_loss = NLLLoss(ignore_index=PAD)      # 该 batch 内所有有效 token 的平均 NLL
ppl_batch = exp(ctx_loss)                 # 该 batch 的 PPL
overall_ppl = exp(mean_batch(ctx_loss))   # 批次等权平均后取指数
```

当 `batch_size=1` 时，批次等权 = **样本等权**，故 Test_PPL 为**样本级（macro）口径**。

### 2. 可比性裁决

| 数据集 | 口径 | 数值 | 可否与 Test 相减 |
| :--- | :--- | :---: | :---: |
| Test（本次 32.4829） | batch=1，样本级 | 32.4829 | — |
| Test（Trial 9 云评测） | batch=1，样本级 | 32.7836 | ✅ 同口径可比 |
| Test（Trial 9 本地复算） | batch=1，样本级 | 32.7774 | ✅ 同口径可比 |
| Test micro（Trial 9，token 级重聚合） | batch=1 数据，token 级加权 | 39.2672 | ❌ 禁止相减 |
| Valid（训练期） | batch=32，`shuffle=False`（F1 后） | 37.3144 | ❌ 禁止与 Test 相减 |

**结论**：`32.4829 vs 32.7836` 是合法的同口径对比；`Valid 37.3144 vs Test 32.4829` 的 4.83 落差**主因是口径差异**（样本级 vs 近 token 级），不可表述为泛化能力，参见铁律 III 与阶段 0 报告第四章。

### 3. 一项口径细节更正（历史文档表述）

阶段 0 报告第四章的表格将 `Valid batch=32` 与 `Test batch=1` 两行并置，但在同一测试集数据上给出 macro 32.7774 与 micro 39.2672。经本轮核验：**macro/micro 的差异来自聚合方式（批次等权 vs token 等权），而非 batch_size 本身**；两次测算的 Test 数据均为 `batch_size=1`。该表所标注的 `batch_size` 列对 Test 行语义不完整，建议后续修订为"聚合口径"列，以免被误读为"batch 不同导致口径不同"。

## 附 B：缺陷 D6（Test MIM_loss 读数）根因定位（本轮结案）

### B.1 直接成因：代码中已显式定义

[`src/models/CASE/model.py:1844-1852`](../../../src/models/CASE/model.py) 对 MIM 损失设置了两条置零闸门：

```python
# === [Phase 7 / A5 修复] MIM 负采样退化与冻结期判定 ===
# 1) 分类头冻结后 (is_currently_frozen) 已关闭 MIM 优化，评测时同步置零保持语义一致；
# 2) 当 bsz <= 1 时 (如测试集逐句解码评估)，In-Batch 错位负采样 (roll) 退化为正样本自身 (fake==real)，
#    导致 logits - fake_logits 恒为 0，sigmoid 距离为 0.5，BCE 损失退化为数学伪常数 -ln(0.5)=0.6931
#    (加权均值恒为 1.1378)。在此无有效负样本情形下安全置零。
if is_currently_frozen or bsz <= 1:
    mim_loss = torch.tensor(0.0, device=config.device)
else:
    mim_loss = config.coarse_weight * coarse_mim_loss + config.fine_weight * fine_mim_loss
```

### B.2 关于 1.1378 的数值性质（含一处不可确证的说明）

代码注释声称"加权均值恒为 1.1378"。需要说明的是：

```
coarse_weight = 1.0, fine_weight = 0.2
若伪常数 = 1.0 × ln(2) + 0.2 × ln(2) = 1.2 × 0.693147 = 0.831776   （不等）1.1378
```

即**简单的两层加权无法复现 1.1378**。其精确来源（可能涉及 `coarse_mim_loss` / `fine_mim_loss` 内部的 `cs_loss + concept_loss`、`cs_loss + react_loss` 各自复合后的元素计数权重）**本次未核验，不作断言**。

**可确证的部分**：`1.1378` 是"无有效负样本时 BCE 退化为 `-ln(0.5)`"这一机制的产物，属数学伪常数，**不携带模型性能信息**。这一点由代码注释与 `bsz <= 1` 的置零分支共同支撑，与阶段 0 报告的判断一致。

### B.3 对本项目的影响（需要更正一处历史解读）

| 观测 | 成因 | 是否可用 |
| :--- | :--- | :--- |
| Test MIM_loss = 1.1378（历史报告） | `bsz <= 1` 路径（测试集逐句解码）+ 置零修复**未落地时的旧代码** | ❌ 伪常数，无信息 |
| Test MIM_loss = 0.0（Trial 9 / Trial 10 / 本地诊断） | `bsz <= 1` 或 `is_currently_frozen` 触发置零（修复后代码） | ❌ 恒零，同样无信息 |
| Valid MIM_loss ≈ 1.062（云端训练期，batch_size=32） | **真实计算值**（有有效批内负样本） | ✅ 可用 |

**因此：Test 侧的 MIM_loss 无论显示 1.1378 还是 0.0，都不具备跨版本可比性，也不构成任何结论。** 此前若将其差异解读为"读数异常/通道污染"，方向不准确——真实原因是**评测路径（`bsz<=1`）与置零修复的版本差**，而非未知污染。此项应从"未查明缺陷"改判为"已定位的口径限制"。

**对论文的影响**：MIM 相关的有效性论证只能使用 **Valid 侧（batch_size=32）** 的读数；Test 侧 MIM 不得进入任何表格或结论。此项同时印证了本报告第八章第 4 节的边界声明——云端与本地 Valid 侧 MIM 平台差（+0.072）确属真实差异，但其物理解释仍待专项排查。

## 附 C：KL_Loss 与 MIM_Loss 的计算定义（口径固定）

因为这两个指标在跨模式对照中出现系统性偏移，此处把代码级定义固定下来，供后续任何引用时核对口径。

### C.1 KL_Loss：注意力分布散度，**不是**变分潜在 KL

[`src/models/CASE/model.py:1797-1802`](../../../src/models/CASE/model.py)：

```python
# distribution alignment
concept_kl_loss = self.criterion_kl(torch.log(prior_concept_attn + 1e-20),
                                    posterior_concept_attn.detach())
cs_kl_loss      = self.criterion_kl(torch.log(prior_cs_attn + 1e-20),
                                    posterior_cs_attn.detach())
kl_loss = cs_kl_loss + concept_kl_loss
```

- `self.criterion_kl = nn.KLDivLoss(reduction="mean")`（[model.py:1328](../../../src/models/CASE/model.py)）；
- 两个张量均为**注意力分布**，形状 `[bsz, seq, seq]`；`reduction="mean"` 在**全部元素**上取均值，故读数随 `bsz` 与 `seq` 同时变化；
- `posterior_*.detach()`：目标侧不接收梯度，梯度只经 `log(prior)` 流动——即"把先验注意力对齐到后验"，而不是双向对齐；
- 值域无上界（非概率意义上的散度），量级 O(0.01~0.1)。

**推论**：该读数随批组成改变是定义层面的必然而非训练异常——因为 `mean` 聚合的样本集合变了，且注意力分布本身由整批的上下文构成。

### C.2 MIM_Loss：批内错位负采样，**依赖批次大小**

[`src/models/CASE/model.py:1804-1852`](../../../src/models/CASE/model.py)：

```python
cs_fake_enc = torch.cat((cs_enc[-1].unsqueeze(0), cs_enc[:-1]), dim=0)   # 批内 roll 错位
...
if is_currently_frozen or bsz <= 1:
    mim_loss = torch.tensor(0.0, device=config.device)
else:
    mim_loss = config.coarse_weight * coarse_mim_loss + config.fine_weight * fine_mim_loss
```

- 负样本由**批内循环错位**（`roll` / `cat` 位移一位）构造，是 In-Batch Negative 的变体；
- `bsz <= 1` 时正负样本重合，读数退化为伪常数（附 B 已给出 1.1378 = `-ln(0.5)` 的来历）；
- `coarse_weight = 1.0`、`fine_weight = 0.2`（[main.sh](../../../main.sh)），复合后读数由两部分加权构成。

**推论**：`bsz` 从 32 降到 4（本地的物理批）时，负样本池从 32 个缩到 4 个，负采样难度与分布都会改变，因此 MIM 读数**不具备跨模式可比性**。

### C.3 对铁律 III 的补充

铁律 III 现行条文针对 PPL 的 macro/micro 口径。本轮新增两项同类约束，建议在下一轮修订规则时并入：

2. **KL_Loss 与 MIM_Loss 不得跨 batch_size 比较**——两者的计算定义均含批内结构。

## 附 D：4G/24G 等效性的两处量级不等价（γ 分歧的机制候选）

第八章确认了"超参全等、仅批组成不同"，但"批组成不同"本身需要一个可量化的机制才能解释 γ 的符号分歧。本轮定位到两处**实际存在的量级不等价**。

### D.1 缺陷 D8：`--max_grad_norm` 全程未生效

- 注册点：[config.py:61](../../../src/utils/config.py) `parser.add_argument("--max_grad_norm", type=float, default=2.0)`；
- **使用点：`src/` 全域检索 `clip_grad` / `max_grad_norm` 零命中**（仅 config 注册处）；
- 结论：两端训练**均未执行梯度裁剪**，日志中的 `max_grad_norm: 2.0` 与其"已启用"的视觉印象均无实际效果。这与 D1（`--use_arc_margin` 漏传）、D5（`print_opts` 只打印真值）属同一类结构性隐患。

### D.2 缺陷 D9：梯度累加未归一化（导致本地有效更新步长偏大）

[model.py:2154-2162](../../../src/models/CASE/model.py)：

```python
loss.backward()                       # 未除以 accum_steps
...
if (iter + 1) % accum_steps == 0:
    opt.step()                        # 每 8 次迭代更新一次
```

- 本地的 8 次 micro-batch 梯度是**累加**而非平均，故累积梯度的量级约为单批的 8 倍（方向为 8 个梯度的矢量和）；
- **Noam 调度器提供了部分补偿**：[common.py:828-844](../../../src/models/common.py) 的 `self._step` 按**优化器更新次数**计数，`lr = factor × d_model^(-0.5) × min(step^(-0.5), step × warmup^(-1.5))`。云端（`warmup=2000`、1 万次更新）与本地（`warmup=16000` 迭代 = 2000 次更新、1 万次更新）的 Noam 轨迹**严格一致**，因此"真实学习率"本身没有偏差；
- **但补偿不完整**：梯度量级差 8 倍 + 无裁剪 ⇒ 本地每个优化器步的**有效参数更新幅度**大于云端（Adam 的一阶/二阶矩归一只能部分吸收整体缩放，且不存在 SGD 式的自动补偿）。

### D.3 与本报告结论的关系

| 结论 | 状态 |
| :--- | :--- |
| 两模式"超参全等、仅批组成不同" | 仍成立（配置层面确实全等） |
| γ 符号分歧的机制 | **候选定为 D9（累加未归一）**：本地有效更新步长偏大 + 8 倍梯度噪声平滑，与观测到的"本地 γ 平滑单调上升 / 云端 γ 平滑单调下降"形态相容 |
| 该机制是否成立 | **未验证**。可检验路径：在 24G 模式下把 `accum_steps` 设为 8 并同步除以累积步数（或反之**移除除法的补丁**做对照），观察 γ 方向是否翻转 |
| PPL 收敛且反超的现象 | 与 D9 相容：更大的有效步长在 PPL 上表现为更快下降（本地后期反超），在门控参数上表现为更强的同向漂移 |

> **边界**：D9 是**配置复现层面的缺陷**，不影响云端 Trial 10 主结果的成立（云端 `accum_steps=1`，D9 对其**无作用**）。它影响的只有"4G/24G 等效"这一方法论表述，以及后续任何以小批量+累加模拟大批次的实验对照。**建议将 D9 修复后再做 4G/24G 对照，否则该对照的结论不可采信。**
