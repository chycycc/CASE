# CASE-EPCL V8.1 实验设计与双轨攻坚全景规划

## 一、项目定位与核心反思

### 1. 核心任务定位
- **课题核心定位**：CASE-EPCL 共情对话生成（Empathetic Response Generation）。
- **学术优先原则**：**本课题的核心目标是“高质量回复文本生成（低 PPL、高多样性 Distinct-1/2、高共情度）”，而不是辅助的情感分类任务（EMO_acc）！**
- **情感准确率定位**：情感分类（CE）与原型对比（EPCL）属于多任务辅助约束，其指标只要稳在 **40.0% 左右基准线不出现大幅滑坡** 即可，彻底放弃在生成最优权重上非要强求辅助分类达到 41.5%+ 的内耗。

### 2. V8 实验核心复盘与痛点反思
- **成功经验**：
  1. **V8 Trial 2 验证了生成单任务让渡的有效性**：在后半程切断辅助梯度后，解码器获得自由度，验证集困惑度打出历史极佳的 **32.62**（成功击穿项目基线 32.80）。
  2. **V8 Trial 4 验证了无似然损失（Unlikelihood）对多样性的飞跃提升**：核采样 Distinct-2 达到 **63.27%**（创全场历史新高，基线仅 30% 左右），彻底解决了对话生成死板复读的问题。
- **现存痛点**：
  1. **硬冻结的副作用**：第 28,000 步硬锁死分类头参数（requires_grad=False），导致后半程编码器为了优化生成产生的自适应微调使分类头脱节，测试集 EMO_acc 跌至 39.39% ~ 39.66%。
  2. **生成端缺乏显式共情偏置**：当前解码器的词表输出只依赖自回归隐层，学到的高质量原型对齐向量 emotion_enc 没有直接作用于词表预测概率，共情词的生成率缺乏显式机制驱动。

## 二、V8.1 双轨实验方案规划

为了全面对比并验证最佳生成效果，V8.1 将完整实施并对比两条路线：
- **方案一（V8.1-Trial A）**：端到端多任务平稳协同 + KEMP 词表层情感偏置注入（彻底取消人工硬冻结）
- **方案二（V8.1-Trial B）**：时序软退火解耦 + 复合早停机制（保留阶段解耦，冲击极限生成 PPL）

---

## 三、方案一：路线 A（端到端多任务平衡 + 词表层情感偏置）

### 1. 理论设计与学术依据
- **取消硬冻结**：全程保持分类头与主干联合训练。由于特征与分类头自始至终同步更新，消除脱节，EMO_acc 自然稳在 40.2% ~ 40.8%。
- **借鉴 KEMP (AAAI 2022)**：*Knowledge-Enriched Empathetic Dialogue Generation*。
  将 Arc-EPCL 高度对齐的 300 维全局共情表征 emotion_enc 直接投影到词表空间，作为自回归输出分布的先验偏置（Emotion-Aware Vocabulary Bias）：
  ```text
  base_logit = W_vocab(pre_logit)
  emo_bias = W_emo(emotion_enc).unsqueeze(1)
  final_logit = base_logit + sigmoid(gate) * emo_bias
  ```
  其中 W_emo 为 300 -> vocab_size 的线性映射，gate 为可学习门控标量（初始值设为 0.1）。
- **学术意义**：不仅降低 PPL，更强迫模型在生成回复时优先激活与输入情感类别共鸣的共情词汇（如安慰、支持、感激类词汇）。

### 2. 精确代码修改规范
- **修改文件**：`src/models/CASE/model.py`
  1. 在主模型 `__init__` 中新增词表情感投影头：
     ```python
     # [V8.1 路线 A] 解码端情感词表偏置投影层
     self.emo_to_vocab = nn.Linear(config.hidden_dim, config.vocab_size)
     self.emo_bias_gate = nn.Parameter(torch.tensor(-2.0)) # sigmoid(-2) 约 0.119
     ```
  2. 在前向解码与词表预测处（`pre_logit` 之后）：
     ```python
     # 注入情感偏置
     emo_vocab_bias = self.emo_to_vocab(emotion_enc).unsqueeze(1)
     logit = self.projector(pre_logit) + torch.sigmoid(self.emo_bias_gate) * emo_vocab_bias
     ```
  3. 在 `decoder_greedy` 和 `decoder_topk` 中同步应用该情感偏置。
  4. 移除 `is_currently_frozen` 的物理切断逻辑，保持 `requires_grad = True`。

### 3. 预期指标目标
- **困惑度 (PPL)**：32.80 ~ 33.20（兼顾多任务）
- **情感准确率 (EMO_acc)**：**40.2% ~ 40.8%**（彻底稳住）
- **多样性 (Distinct-2)**：**> 60.0%**（保持无似然损失 unlikelihood_weight = 0.10）
- **共情词生成度**：显著提升，词表预测直接受原型表征偏置引导。

## 四、方案二：路线 B（平滑软退火解耦 + 复合早停，极限单任务生成）

### 1. 理论设计与学术依据
- **尊重阶段解耦初心**：承认前期多任务塑形与后期单任务生成的学术直觉，追求极限 PPL。
- **废除硬冻结，改用平滑余弦退火（Soft Loss Annealing）**：
  在总损失计算中，不对分类头执行参数锁死，而是将辅助损失权重通过余弦曲线平滑衰减至极微弱水平：
  - `0 ~ 24,000` 步：多任务全开（lambda_epcl = 0.15, w_emo = 1.0）；
  - `24,000 ~ 40,000` 步：余弦退火，辅助损失权重从 1.0 平滑降低至 0.05；
  - `40,000 ~ 52,000` 步：单任务生成主导，保留 0.05 的极微弱梯度，既防止分类头退化，又不干扰语言生成。
- **重构检查点保存判据（复合早停）**：
  在 `main.py` 中，淘汰只看 `ppl_val <= best_ppl` 的机制，改用平衡评分：
  ```text
  composite_score = valid_ppl - 20.0 * valid_emo_acc
  ```
  杜绝为了 0.01 的 PPL 降低而保存分类头严重退化的坏权重。

### 2. 精确代码修改规范
- **修改文件 1**：`src/models/CASE/model.py`
  在计算总损失处，增加时序权重衰减：
  ```python
  if train and iter >= 24000:
      progress = min((iter - 24000) / 16000.0, 1.0)
      soft_weight = 0.05 + 0.95 * 0.5 * (1.0 + math.cos(math.pi * progress))
  else:
      soft_weight = 1.0
  ```
  将其同时作用于 `emotion_loss` 与 `epcl_loss`，分类头保持微弱更新。
- **修改文件 2**：`main.py`
  将验证集保存逻辑由单看 PPL 升级为 `composite_score` 最小化判定。

### 3. 预期指标目标
- **困惑度 (PPL)**：**32.30 ~ 32.50**（冲击全场历史最低）
- **情感准确率 (EMO_acc)**：**39.8% ~ 40.2%**（平滑退火守住基准线）
- **多样性 (Distinct-2)**：**> 60.0%**

## 五、双轨实验对比横向维度

| 评估维度 | 方案一 (路线 A: 端到端 + 情感词表注入) | 方案二 (路线 B: 软退火 + 复合早停) |
| :--- | :--- | :--- |
| **训练机制** | 全程多任务联合微调，架构干净优雅 | 前期多任务，后期余弦退火平滑让渡 |
| **分类头状态** | 全程动态更新（requires_grad=True） | 全程微弱更新（保持 0.05 极弱梯度） |
| **困惑度 (PPL) 预期** | 32.80 ~ 33.20 | **32.30 ~ 32.50（极限最低）** |
| **情感准确率 (EMO_acc)** | **40.2% ~ 40.8%（最高）** | 39.8% ~ 40.2%（稳健守线） |
| **回复共情相关性** | **显著提升（词表层显式情感偏置）** | 依赖隐藏层表征的隐式传递 |
| **多样性 (Distinct-2)** | > 60.0% | > 60.0% |

## 六、执行 SOP 与环境安全红线

1. **显存安全约束**：单卡 RTX 3050 (4GB)，严禁引入高维显存冗余，词表映射层务必在 fp16 (autocast) 下计算。
2. **磁盘管理红线**：每个 Trial 训练完成后，必须在当前轮次内物理销毁全部非最优检查点，仅保留 1 个黄金权重，确保可用空间 > 12 GB。
3. **评测闭环规范**：每个 Trial 训练完毕后，必须运行 `src/scripts/eval_v8_pipeline.py`（贪婪解码 + 核采样双轨）提取完整指标，并输出流形对齐与聚类指标。
