# CASE-EPCL V8.2 D 终局全量达标设计与行动方案

> **文档定位**: 基于 V8.2 C 实测数据的严格自审，定位 2 项未达标指标（Test PPL 32.84 vs 目标 ≤32.50、EMO_loss 2.2999 vs 目标 ≤2.1500）的底层代码漏洞与训练动态失衡根因，制定 3 项精准修复措施，同时严格防守 C 计划中已达标的 4 项指标不退化。

### 1.2 根因定位（三层机理）

#### 根因 A：评估阶段 `current_step` 覆盖漏洞（代码级 Bug）

[`model.py` L1523-1524](file:///e:/github/CASE/src/models/CASE/model.py#L1523-L1524) 的 `train_one_batch` 方法在每次调用时无条件覆盖 `self.current_step`：

```python
def train_one_batch(self, batch, iter, train=True):
    self.current_step = iter  # ← 无论 train=True/False，都会执行
```

当训练期间调用 [`common.py` L992](file:///e:/github/CASE/src/models/common.py#L992) 的 `evaluate()` 做验证集评估时，传入 `iter=0`，导致 `current_step` 被重置为 0。而 `get_bias_scale()` 在 `step <= bias_anneal_start` 时返回 1.0，因此**训练期间所有验证集 PPL 均在满额偏置 (`bias_scale=1.0`) 下计算，系统性偏高**。

同样地，`eval_v8_pipeline.py` 虽然在加载权重后恢复了 `model.current_step = 39999`（[L214](file:///e:/github/CASE/src/scripts/eval_v8_pipeline.py#L214)），但 `evaluate_test_set()` 内部调用 `train_one_batch(batch, 0, train=False)` 时立即将其重置为 0（[L244](file:///e:/github/CASE/src/scripts/eval_v8_pipeline.py#L244)）。

**直接后果**：
- V8.2 C 的 Test PPL 32.84 是在 `bias_scale=1.0` 下测量的，但模型训练时在 39,999 步实际使用的 `bias_scale≈0.80`。满额偏置对 15% 实词叠加了概率底噪，直接限制了 PPL 向 32.50 下探。
- 验证集 PPL 的检查点遴选基准存在系统性偏差（全部以满额偏置评估），最优检查点可能出现在不同步数。

#### 根因 B：PPL 与 EMO_loss 之间的帕累托对抗与检查点遴选缺陷

从 V8.2 C 验证集训练轨迹（摘自 `train.log`）可清晰观察到：

| Step | Val PPL | Val EMO_loss | 评价 |
| :---: | :---: | :---: | :--- |
| 23999 | 40.19 | **2.0249** | EMO_loss 全程最优 |
| 27999 | 38.62 | 2.0826 | EMO_loss 达标 |
| 33999 | 38.12 | 2.1359 | EMO_loss 仍在 2.15 附近 |
| 35999 | 38.05 | **2.2334** | EMO_loss 开始恶化 |
| **39999** | **37.10** | **2.3106** | PPL 最优 → 被选为检查点 |
| 45999 | 37.16 | 2.4836 | EMO_loss 持续恶化 |

[`main.py` L165](file:///e:/github/CASE/main.py#L165) 中 `is_score_better = (ppl_val <= best_ppl)` 仅以验证集 PPL 为唯一标准，完全忽略 EMO_loss。模型选择了 PPL 最优但 EMO_loss 已恶化至 2.31 的 39,999 步权重。

#### 根因 C：训练后半程分类头梯度刚度不足

生成自回归损失的数值量级（10~15）远大于分类交叉熵（2~3）。尽管对称 PCGrad 在冲突时互相正交化，但在非冲突更新时（$\langle \mathbf{g}_{\text{gen}}, \mathbf{g}_{\text{emo}} \rangle \ge 0$），两组梯度直接相加，高量级的生成梯度对共享表征的参数更新依旧主导。且学习率在后半程已衰减至 $\sim 1\times 10^{-5}$，分类头更新步长极小，无法及时修正共享表征的漂移。

## 二、 V8.2 D 三项精准修复方案

### 2.1 修复 `current_step` 评估覆盖漏洞 [零风险]

#### [MODIFY] [`src/models/CASE/model.py`](file:///e:/github/CASE/src/models/CASE/model.py)

在 `train_one_batch` 方法中加入保护：仅当 `train=True` 时更新 `self.current_step`。

```python
# 修复前 (L1523-1524):
def train_one_batch(self, batch, iter, train=True):
    self.current_step = iter

# 修复后:
def train_one_batch(self, batch, iter, train=True):
    if train:
        self.current_step = iter
```

**影响范围**：
- 训练期间验证集评估将使用当前真实训练步数的 `bias_scale`，而非固定的 1.0；
- 测试集评估将使用从检查点文件名恢复的真实步数对应的 `bias_scale`；
- 不改变任何训练动态，仅修正评估测量的准确性。

### 2.2 偏置退火区间调整与下限压缩 [低风险]

#### [MODIFY] 流水线脚本超参数（不修改 `model.py` 内部逻辑）

| 超参数 | V8.2 C 值 | V8.2 D 值 | 调整理由 |
| :--- | :---: | :---: | :--- |
| `--bias_anneal_start` | 35000 | **30000** | 提前 5k 步开始退火，使偏置衰减在 40k 步完整到达下限 |
| `--bias_anneal_steps` | 15000 | **10000** | 退火跨度从 15k 压缩至 10k，加速下降 |
| `--bias_min_scale` | 0.20 | **0.15** | 下限从 0.2 降至 0.15，进一步压缩概率底噪 |

退火曲线关键节点：

| Step | Bias Scale (V8.2 C) | Bias Scale (V8.2 D) |
| :---: | :---: | :---: |
| 25000 | 1.0 | 1.0 |
| 30000 | 1.0 | **1.0 (退火起点)** |
| 35000 | 1.0 (退火起点) | **0.575** |
| 40000 | 0.80 | **0.15 (退火终点)** |
| 45000 | 0.50 | 0.15 |

调整后的好处：
- 前 30k 步依然保留全额偏置，保护多样性学习充分内化（Greedy Dist-2 安全防线）；
- 在 36k~40k 步的检查点窗口内，模型已处于 0.15~0.30 的低偏置状态，PPL 测量更真实。

### 2.3 后半程动态情感损失权重提升 + 帕累托复合检查点遴选 [中风险]

#### [MODIFY] [`src/models/CASE/model.py`](file:///e:/github/CASE/src/models/CASE/model.py) — 情感损失权重动态提升

在情感损失计算区域（`emotion_loss` 赋值之后），增加后半程线性放大逻辑：

```python
# 在 emotion_loss 确定之后 (约 L1854 之后):
if getattr(self, 'use_emo_loss_ramp', False) and train:
    ramp_start = getattr(self, 'emo_loss_ramp_start', 24000)
    ramp_steps = getattr(self, 'emo_loss_ramp_steps', 16000)
    ramp_max = getattr(self, 'emo_loss_ramp_max', 1.5)
    if iter >= ramp_start:
        progress = min(1.0, float(iter - ramp_start) / float(ramp_steps))
        emo_w = 1.0 + (ramp_max - 1.0) * progress
        emotion_loss = emo_w * emotion_loss
```

权重曲线：

| Step | 情感损失权重 |
| :---: | :---: |
| 0 ~ 24000 | 1.0 |
| 24000 | 1.0 (开始上升) |
| 32000 | 1.25 |
| 40000 | 1.5 (到达上限) |

#### [MODIFY] [`main.py`](file:///e:/github/CASE/main.py) — 帕累托复合检查点遴选

在现有的 `use_composite_score` 基础上，新增 `emo_loss` 模式（[`main.py` L156-167](file:///e:/github/CASE/main.py#L156-L167)）：

```python
if getattr(config, 'use_composite_score', False):
    composite_mode = getattr(config, 'composite_mode', 'acc')
    if composite_mode == 'emo_loss':
        alpha = getattr(config, 'composite_emo_loss_weight', 8.0)
        cur_score = ppl_val + alpha * emo_loss_val
        score_info = f"Score={cur_score:.4f} (PPL={ppl_val:.4f}, EMO_loss={emo_loss_val:.4f})"
    else:
        # 既有的 acc 模式
        composite_acc_weight = getattr(config, 'composite_acc_weight', 20.0)
        cur_score = ppl_val - composite_acc_weight * emo_acc_val
        score_info = f"Score={cur_score:.4f} (PPL={ppl_val:.4f}, EMO_acc={emo_acc_val:.4f})"
    is_score_better = (cur_score <= best_score)
```

$$\text{Score} = \text{PPL}_{\text{val}} + \alpha \cdot \text{EMO\_loss}_{\text{val}}$$

$\alpha = 8.0$（从 V8.2 C 验证集轨迹推导：PPL 跨度 ~3 点 vs EMO\_loss 跨度 ~0.28，量纲比约 6:1，取 8.0 留出裕量确保 EMO\_loss 改善贡献可靠超过同等幅度 PPL 退让）。该公式同时惩罚高 PPL 和高 EMO\_loss，在帕累托前沿遴选全局平衡最优的检查点。
